# 五步設計案例：會議記錄幫手

[回補充篇](../field-notes.zh-TW.md) · [產物驗收表](../../templates/ARTIFACT-CHECKS.md)

**狀態：教學設計，尚未實作。** 取材自使用者提供的同名課程增補稿（@Luo Zih-Jia），經整理並補上驗收限制。Repo 沒有 STT、摘要、Mermaid 量測或寄信應用；此頁沒有假裝可執行的管線指令。想立即執行案例，請用既有[捲動 fixture](../../examples/scroll-drift/README.md)。

目標：錄音 → 逐字稿 → 四段摘要 → Mermaid 圖 → 測試信件。先證明每個產物符合需求，再決定是否對外提供服務。

## 1. 定義完成：先寫好如何判錯

可用提示：

```text
我要做會議記錄幫手：錄音轉文字、四段摘要、Mermaid 圖與測試信件。
請先釐清讀者、輸入限制、語言、資料使用範圍與完成條件，寫成 SPEC。
每條條件列出預期產物、通過方式與一個會失敗的例子。
沒有說出的負責人、日期或決議要標未確認，不得自行補成事實。
這階段只做規格，不實作、不寄真實信件。
```

以下門檻是待專案確認的起點，不能直接當通用標準：

| ID | 驗收條件 | 故意做錯的樣本 |
| --- | --- | --- |
| A1 輸入 | 約定格式與最長時間；空檔、不支援格式有明確錯誤 | 空錄音、損毀檔、超長錄音 |
| A2 STT | 固定錄音與人工校對稿，依約定的文字正規化及 CER 門檻比對 | 空逐字稿、漏掉關鍵句 |
| A3 摘要 | 目的、決議、待辦、未決問題四段；對照標註的 3 項決議與 4 項待辦，內容完整且不虛構 | 漏一項決議、把提案寫成決議、編造期限 |
| A4 圖 | 能渲染；在約定交付尺寸下可讀；支援的節點文字不出框；內容對應摘要 | 語法錯、細字、文字裁切、錯誤關係 |
| A5 信 | 在隔離測試收件匣讀回本次執行的信；收件人、摘要、圖與預期一致 | 別次執行的舊信、缺圖、錯收件人 |
| A6 失敗 | STT、摘要、渲染或寄送失敗時，清楚回報並停止後續交付 | 渲染失敗後仍寄出「成功」信 |
| A7 重試 | 重試使用本次工作識別碼與明確的重寄政策，不意外重複寄送 | 逾時重試造成兩封信 |

「待辦有期限欄位」與「會議真的說了期限」不同。欄位可用 `null` 表示未知並附狀態，人工確認後才成為期限；要求必填日期會鼓勵編造。

## 2. 自我驗證：讓每一段留下可追溯的證據

先用合成或已獲准的錄音建立標註資料，另保留未用來調整提示的樣本，避免只對示範錄音有效。

| 階段 | 實作檢查時要量什麼 | 不能據此宣稱什麼 |
| --- | --- | --- |
| STT | 約定正規化後的錯誤率、關鍵詞錯誤；保留逐字稿差異 | 單一錄音通過代表各口音、雜訊都正確 |
| 摘要 | 每個預期項目是否被正確表達、是否有無來源主張 | 標題齊全或關鍵字命中代表語意正確 |
| 圖 | 實際渲染、字型載入、交付尺寸、支援節點的幾何與截圖 | 能輸出 SVG 代表圖一定好看 |
| 信件 | 用本次 run ID／message ID 找到對應信，讀回正文與圖片資料 | 測試伺服器收到代表外部信箱一定可投遞 |
| 全流程 | 全新輸出目錄、各階段狀態、輸入與產物雜湊、失敗訊息 | 檢查器本身沒報錯代表應用已執行完 |

Mermaid 的字級與節點數可先試用 16px／12 節點，再按實際展示效果調整。量測器需在找不到外框、標籤、字型或遇到不支援形狀時明確失敗；幾何限制與一手來源見[補充篇](../field-notes.zh-TW.md)。寄信前要檢查**最後使用的圖片**，不要只看未縮放的 SVG。

總檢查入口應做到：清理或隔離舊產物、逐條執行 A1–A7、保留各階段輸出，任何必要條件失敗或未執行都不能回報全過。先測正確樣本，再逐一注入上表錯誤。Stop hook 只是呼叫入口的一個方式，仍需獨立 CI；現成 wrapper 的範圍見[邊界範例](../../templates/boundaries/README.md)。

## 3. 獨立審查：連測試一起審

把 SPEC、diff、測試樣本與[證據回報](../../templates/EVIDENCE.md)交給未參與實作的 reviewer：

```text
請唯讀審查 A1–A7 是否實作，保留行為與失敗路徑是否有證據。
檢查摘要是否憑空補資料、幾何檢查是否漏掉未量測節點、收信是否對應本次執行。
確認每條必要檢查對故意做錯的樣本會失敗，而且敗在正確條件。
只回報可重現的正確性缺口、影響與缺失證據，跳過風格偏好，不修改程式。
```

另挑不同長度與結構的三份產物，在真實展示尺寸做視覺和語意審查。這是抽樣，不能稱為所有可能會議都已驗證。

## 4. 確定性邊界：管住資料與寄送出口

- 開發環境只連隔離收件匣，例如本機 Mailpit；部署層禁止該環境直接連外部 SMTP／寄信 API。測試不使用正式寄信憑證。
- 收件人白名單在實際寄信服務與帳號權限執行；用禁止目的地測試，確認不會產生外部寄送。只比對某段 shell 命令的 hook 無法涵蓋所有 SDK、HTTP 或 MCP 路徑。
- 錄音與逐字稿的讀寫、保存期限、可送往哪些服務先列明；秘密不放進公開 fixture 或證據。設定應以無權讀取的合成測試檔驗證，不用真金鑰測外洩。
- 第一封真實交付需要對收件人與內容的明確核准；日後自主寄送也須先定義授權範圍、重試與撤銷方式。

Sandbox、deny 與工具範圍需分別核對，詳見[補充篇的一手文件](../field-notes.zh-TW.md)。本頁沒有宣稱這些環境已配置或測過。

## 5. 教訓進結構：保留錯誤樣本

| 再次出現的問題 | 放進結構 | 如何證明有效 |
| --- | --- | --- |
| 圖在信件裡字太小 | 最終圖片尺寸與可讀性檢查 | 舊的縮小圖片必須失敗 |
| 摘要編造期限 | 可表達未知的 schema、來源對照與語意審查 | 沒說期限的錄音不能產生確定日期 |
| 圖有節點沒被量到 | 節點數與可量測數對照，不支援就回報 | 缺標籤／不支援形狀不能全綠 |
| 讀到別次執行的信 | 端到端 run ID 與 message ID 對照 | 舊信留在收件匣時仍抓得到本次缺信 |
| 差點寄到真實信箱 | 測試 transport 隔離與目的地限制 | 禁止目的地被拒，且無外部寄送 |

依 [LESSONS](../../templates/LESSONS.md)保留真實錯誤、修正與驗證方式。完成時交付 SPEC、驗收矩陣、可重現的測試證據、產物預覽與未涵蓋範圍；不能把這份設計文件當成已完成的產品。
