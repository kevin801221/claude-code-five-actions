## 1. Regression 失敗自動分類

**故事：**身為數位 IC 驗證工程師，我想讓每晚失敗的 case 依原因分類，早上先看真正的新問題。

- **定義完成：**和工程師確認類別、未知、混合原因與「新問題」的定義。類別名稱進 GLOSSARY；不明確的 log 可拒答，不能為了提高分類率硬猜。
- **資料與證據：**可先收集 200 份已標註 log，按問題家族拆成調整用與保留驗證集，避免同根因的近似 log 同時落兩邊。回報每類 precision／recall、混淆矩陣、未知比例與樣本數；總一致率不能掩蓋少數重要類別失敗。
- **故意做錯的樣本：**把 timeout 與 assertion 的線索混在一起，或放入未見過的環境錯誤。檢查是否回報歧義／未知，而非自信地錯分。
- **邊界：**只讀 log、只產出分類建議，不修改 regression 設定，不自動關 bug。用檔案與帳號權限落實，不只寫在 prompt。
- **教訓：**保留誤分類案例，修正類別或規則後重跑保留集；不把測過的答案直接塞回提示當成泛化能力。

## 2. Tcl 腳本遷移到新版 EDA 工具

**故事：**身為 CAD 工程師，我想遷移 300 支舊腳本，保留設計結果與必要行為。

- **定義完成：**固定工具版本、設計、設定與種子；先寫明哪些輸出必須完全一致、哪些可在領域核准的誤差內。時間戳與路徑等非語意差異明列正規化規則，不用刪除所有差異來換綠燈。
- **資料與證據：**挑三支代表不同語法及失敗情境的腳本試跑。逐支保存新舊工具輸出、語意比較、版本與退出狀態，再分批擴大。
- **故意做錯的樣本：**新語法能執行，卻忽略一項 constraint。驗收應在結果差異上失敗，不能只有語法檢查。
- **邊界：**獨立工作目錄、只允許修改指定腳本、保存輸入設計、限制每批總時間與資源。`--max-turns` 不是路徑隔離或全批預算；工具語意見[補充篇](../field-notes.zh-TW.md)。結果以 PR 交付，先決定合併授權。
- **教訓：**同一種遷移遺漏再次發生，就把舊腳本與結果差異保留成回歸案例。

## 3. 良率週報與圖表

**故事：**身為測試工程師，我想自動產出趨勢圖與異常批次標記，週會直接閱讀。

- **定義完成：**先固定良率分母、重測處理、缺值、bin、lot 與異常規則；例如重測是否取代首測，不能由 agent 猜。定義與單位寫進 GLOSSARY。
- **資料與證據：**拿一組人工核對的合成歷史資料比對數字與異常清單；在實際投影片或信件尺寸查看圖。自動檢查標籤裁切與單位，再用截圖審查整體可讀性。
- **故意做錯的樣本：**重複計入重測資料、交換 lot 標籤、漏掉異常批次，應分別敗在數值、標籤與內容條件。
- **邊界：**來源資料只讀；輸出移除可識別客戶資訊；先產出預覽供核准。資料庫權限與交付出口各自限制。
- **教訓：**分母錯誤改成資料契約與對照測試；圖表字級改在最終展示尺寸驗收。

## 4. 內部 IP 文件問答

**故事：**身為新進設計工程師，我想問暫存器如何設定，取得有版本與出處的答案。

- **定義完成：**固定可用文件、版本優先序、頁碼／章節格式與拒答條件。正確答案還必須來自使用者有權讀取的來源。
- **資料與證據：**可先準備 30 題附答案、版本與引文位置的問題，加入「找不到」「版本衝突」「無權讀取」題，並保留未參與調整的題目。分開回報答案正確性、引文是否支持主張、拒答結果；引用了文件不代表文件支持答案。
- **故意做錯的樣本：**引文頁碼存在但不支持答案、引用舊版本、查詢無權文件。檢查應抓到各自缺口。
- **邊界：**權限在檢索、索引與回答前都生效；不能只隱藏顯示或靠模型不引用。只讀文件、不把答案自動寫回工程系統。
- **教訓：**保留錯誤引文與版本衝突案例，調整檢索後重跑；證據集規模有限，不能宣稱保證所有問答正確。

## 怎麼帶進課堂

選一個故事，把「要自動化什麼」改寫成「在什麼輸入下，留下什麼可判斷的產物」。再填[驗收矩陣](../../templates/ARTIFACT-CHECKS.md)：一條條件、一個正確樣本、一個故意做錯的樣本、一份本次執行的證據。重點是驗收方法，並不要求裝齊所有流派。
